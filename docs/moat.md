# 独门诀窍在哪 × Toonflow 知识库能不能借

## 一、先回答第二个问题：能借，而且你借得太少

**法律上：能。** Toonflow 是 MIT，覆盖"Software and associated documentation files"。它的方法库在 `packages/skills/` 下，MIT 授权同样适用。你的 `THIRD_PARTY_NOTICES.md` 已经完整保留版权与许可全文，**合规**。

**但你现在只借了 4 份的浓缩版，他们实际有 15 份主文件 + 一个 knowledge 子目录：**

```
references/
  projectSetup.md        项目初始化与归档
  sourceEvents.md        来源与章节事件
  storySkeleton.md       故事骨架
  adaptationStrategy.md  改编策略与边界
  episodeScript.md       逐集剧本
  baseAssets.md          基础资产提取
  generateAssets.md      资产图片制作
  deriveAssets.md        衍生资产分析
  directorPlan.md        单集导演规划（分场/台词统计/情绪浓度/场间过渡）
  storyboardTable.md     分镜表（场→片段→镜头）
  storyboardPanel.md     分镜面板落点
  storyboardImages.md    分镜图
  videoProduction.md     视频准备、生成、验收与**交付边界**
  canvasOperations.md    画布执行

  knowledge/             narrativeGenres / scriptCraft / visualStyles /
```

**借用条件（三条，缺一条就变成风险）**

1. **保留版权与许可**（已满足）。
2. **不冒称原创**。参赛材料里主动写"部分导演与分镜方法整理自 Toonflow（MIT）"——规则要求信息真实，写了是加分。
3. **事实性内容回原始来源**。他们文档里对模型能力、提示词模板的描述会随模型换代过期（他们的 `videoProduction.md` 自己就写着"不强制 Seedance""旧版 README 提及拼接导出，但该 tag 未提供路由，不编造旧 API"）。凡是讲某个模型怎么用的，去查该模型官方文档，别二手转抄。

## 二、但借来的东西，永远不可能是"独门诀窍"

这是最重要的一句：**今天你能借，明天你的对手也能借。**

你现在的工艺手册里，最值钱的部分（12 类叙事技法、11 种画风、题材节拍）恰恰**来自别人的开源仓库**。它证明你能读懂好方法，但它不是护城河，它是起跑线。

**能被复制的东西，列清楚，别自我安慰**：

| 以为是诀窍 | 实际 |
|---|---|
| 19,602 字工艺手册 | MIT 公开知识，任何人今天可 fork |
| 无限画布 + 连线血统 | Toonflow 有画布；连线是一周的工作量 |
| Agent 操作画布 / 27 工具 / 审批 / rewind | 官方 Comfy Agent 正在做，路线图公开 |
| 工作流导入即工具 | 真有摩擦成本，但 ComfyUI 官方在推 subgraph / app 化 |
| ffmpeg 剪辑 / 响度 / 字幕 | 技术上是几十行命令 |
| 26,300 行代码 | 代码不是资产，判断才是 |

## 三、独门诀窍：三层，越往下越硬

### L1｜位置：你站在"交付边界"的另一侧（有硬证据）

Toonflow 自己的方法文档 `videoProduction.md`「交付边界」原文：

> **"默认可交付为按确认顺序排列的片段及清单……用户要求合成时，先核实当前宿主有可用合成能力，再确认具体方案；没有能力时明确交付为片段。"**

它的节点类型也印证：`textNode / imageNode / videoNode / audioNode / imageGenerationNode / videoGenerationNode / audioGenerationNode / frameAnalysisNode / director3dNode`——**没有合成节点**。

这不是他们忘了，是**产品模型的必然**：节点是"生成动作"，而成片不是生成，是一次**组装与判断**。要加它，得引入时间线、台词轨、字幕轨、响度标准、返工范围——那是一套新数据模型，不是一个新节点。

**所以你的位置优势是真的：全行业停在片段清单，你在成片这一侧。**

### L2｜机制：以"修订"为单位，不以"生成"为单位（利益冲突保护）

- 云平台按"次数/积分"卖钱 → 它天然不优化"收敛到能交"，因为收敛意味着少生成。
- 你按"镜头"组织工作 → 单个镜头重做、下游自动重拼、返工成本可预估、阶段可回滚。

这不是技术差距，是**商业模式的盲区**。对手越赚钱，越不想做这件事。

⚠️ 但注意：Toonflow 已经有"阶段确认关口 + 状态机（草稿/待确认/已确认/生成中/失败/待复核）+ 产出契约对照"，**流程可审性他们做得比你现在好**。所以 L2 里"可审"不算你的差异化，**"可审到成片、且修订成本有界"**才算。

### L3｜积累：craft-as-code（唯一会越用越厚的东西）

Toonflow 的 13 步全靠 **文档 + 模型自觉**——门禁写在 SKILL.md 里，靠 LLM 遵守；它没有程序层的硬校验。

你要做的是把手册变成**程序门禁**：

| 手册里的判断 | 变成代码里的什么 |
|---|---|
| 关键帧必须是视频的第 0 秒 | 提交前比对首帧描述与动作时态，不合就拒绝提交 |
| 复杂运镜不能和大动作挤在一个镜头 | 提交前解析运镜与动作字段，冲突就拦 |
| 台词必须完整保留 | 剪辑前用 silencedetect 核对台词位置，被裁就报警 |
| 对白统一 -16 LUFS，环境声不跟着拉平 | 导出前测响度，不达标不出片 |

**为什么这个抄不走**：规则本身能抄，但阈值和例外只有跑过片才调得出来。每失败一次，多一条规则；每条规则背后是一个具体的失败样本。**fork 得到文档，fork 不到你的失败记录。**

这也意味着——**你现在真正的资产是零，因为一条片都没跑过。** 手册是别人的，阈值是猜的，样本没有。

## 四、一句话

> **别家优化"生成得更快"，你优化"改到能交"。**
> 知识库可以借，但借来的只是起跑线；真正的诀窍是"把判断写成会拦住你的代码"，而它只能靠一条条跑废的片子长出来。

## 五、接下来四件事（顺序不能换）

1. **借全**：把上面 15 份里缺的补进来（优先 `directorPlan` / `shotCraft` / `videoPromptCraft` / `sourceMap`），但**重写为可执行规则**，不整段搬运。
2. **立库**：建 `docs/craft/*.md`（版本化，每条规则带 `why: 来自哪次失败`）和 `shared/checks/*.ts`（可测试）。
3. **跑片**：跑通一条 60–90 秒，把每一次失败写进 `docs/craft/failures.md`——从这一刻起你开始拥有别人拿不走的东西。
4. **讲述**：参赛材料只讲一句边界——"主流的 AI 短剧工具默认交付的是片段清单，我们交付的是片"。
