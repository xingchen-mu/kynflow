唯一回退是 `intent-upscale`：增强组先正确提交 `params.scale=2`，读到模拟输出仍为原始 256×128 后再次提交，同一任务产生两个结果。Mock 服务始终返回占位图，不执行实际超分；轨迹显示输出尺寸与任务要求冲突。本轮保持原断言和原始失败结果，没有修改夹具或把它改成通过。因此不能把本次结果概括成整体能力提升，也不能把这一个混杂样本直接外推为真实 GPU 超分失败。后续应完善模拟尺寸语义，再独立复测。

上下文相关用例中，长剧本仍通过，但总 Token 多 3130；只改一个节点的用例多一次调用。当前 Context Builder 改善了焦点选择与信息完整性，尚未证实每类任务都降低成本。单次模型采样和服务端模型别名也限制因果解释。

## 验证边界

`npm test`：286 项通过；`npm run build`、`npm run smoke` 通过。自动回归包括单项失败不能被高分掩盖、证据不足不能通过、旧标准失效、完整视频不能凭抽样验收、Critic 无创作信息、修复映射与上下文预算。真实模型协议实验和真实 GPU 创作结果分开记录，未将模型自评升级为用户确认。

当前结论：第二阶段机制已落地并完成对照；协议决策的资源消耗有所下降，但出现一例混杂回退，真实视觉评分尚未校准，不能宣称整体能力或创作成功率已经提高。
